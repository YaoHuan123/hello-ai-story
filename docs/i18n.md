# 界面语言（i18n）规划

本文说明当前中英文覆盖范围、上线节奏，以及 **Web 先行 + 后台开关** 的用法。原生 iOS/Android 在 Web 验证通过后再接构建变体。

## 当前状态

### 已完成（P0 壳层）

前端 `frontend/src/i18n/` 提供 `zh` / `en` 文案与 `t()`、`displayError()` 等工具。

已接入壳层的页面/模块：

- 登录页、底部 Tab、故事墙、账户页
- 创作首页入口、子页顶栏
- 常见 API 错误码本地化

### 尚未完成

| 层级 | 内容 | 说明 |
|------|------|------|
| **P1** | 子页 **UI** | 访谈、文本、视频子页及生产错误提示已接入 i18n |
| **P2** | **业务生成内容** | 访谈问句、成文正文、口播/字幕、视频风格名等由 LLM + `prompts/` 产出，目前全是中文 |
| **P3** | 英文模板与历史数据 | 英文访谈题库、已有中文访谈数据的迁移策略 |

因此：**`APP_LOCALE=en` 切换的是界面英文**（含访谈/文本/视频子页按钮与状态）；聊天问句、生成文稿正文、视频旁白、风格配置名等**业务内容仍为中文**，直到 P2 落地。

## 上线节奏

```
Web（后台 APP_LOCALE）→ 壳层 + 子页 UI 测通 → iOS/Android（VITE_LOCALE 构建变体）→ P2 英文生成链路（按需）
```

1. **现阶段（Web）**：在 `backend/.env` 设 `APP_LOCALE=zh|en`，前端 Web 启动时从 `GET /api/health` 读取 `locale`，统一整站壳层语言。改 env 后重启 API 即可切换，无需重编前端。
2. **子页 UI（P1）**：在 Web 上分别用 `APP_LOCALE=zh` / `en` 走一遍访谈、文本、视频流程，确认按钮/状态/错误提示双语。
3. **原生包（后续）**：Web 稳定后，iOS/Android 用 `VITE_LOCALE` 在**构建时**写入语言（同一套代码，不同 env 出不同包）。业务内容（P2）仍待单独排期。

## 语言如何决定

### Web 浏览器

| 优先级 | 来源 | 说明 |
|--------|------|------|
| 1 | 后端 `APP_LOCALE` | `GET /api/health` → `locale`；**权威配置**，便于联调与验收 |
| 2 | `VITE_LOCALE` | 仅当 health 不可用或未返回合法 `locale` 时作为构建时兜底 |
| 3 | `navigator.language` | 以上皆无时：`zh*` → 中文，否则英文 |

### 原生 App（Capacitor，暂未切换）

| 优先级 | 来源 |
|--------|------|
| 1 | `VITE_LOCALE`（`.env.ios.local` / `.env.android.local`） |
| 2 | 系统语言 |

原生包**不**依赖 `APP_LOCALE`（避免运行时连错环境）；海外 iOS 计划在 Web 验收后再启用 `VITE_LOCALE=en` 构建。

## 后台开关配置

在 `backend/.env`：

```env
# 界面语言：zh（默认）| en
APP_LOCALE=zh
```

修改后**重启后端**（`npm run dev:backend` 或生产 `pm2 restart`）。前端 Web 刷新页面即可生效。

自检：

```bash
curl http://localhost:3001/api/health
# 响应含 "locale": "zh" 或 "en"
```

开发时前端通过 Vite 代理访问 `/api`，与生产 Web 行为一致。

## 前端文案维护

- 目录：`frontend/src/i18n/locales/zh.ts`、`en.ts`
- 用法：`import { t } from "../i18n"` → `t("login.heading")`
- 带占位：`t("account.joined", { date: "..." })`
- API 错误：在 `api.*` 下按 `code` 补条目；`displayError(err)` 会自动映射

新增壳层或 P1 子页字符串时，**中英文 key 同步添加**。

## P2 业务双语（未做，备忘）

若海外需要**英文访谈与英文成片**，除 P1 UI 外还需：

1. 请求链路传递 `locale`（或后端读 `APP_LOCALE`）
2. `prompts/interview/`、`create-text/`、`create-video/` 等按语言分支或加输出语言约束
3. 英文 TTS 音色、英文字幕/口播校验
4. `video-styles.json` 等配置的英文副本或字段

已有用户用中文作答的数据**不会**自动翻译；换语言更适合新项目或显式「用英文重新生成」。
