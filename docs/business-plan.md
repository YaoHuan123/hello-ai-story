# Hello Story 商业策划书

> 版本：2026-06 · 基于当前代码库与产品文档整理  
> 产品名：**Hello Story** · 定位演进：**AI 故事创作与传播平台**

---

## 一、执行摘要

**Hello Story** 是一款 AI 驱动的**个人与集体故事创作、成片与分发平台**。用户通过移动端与 AI 进行结构化访谈，系统将口述整理成故事正文，并一键生成传记、专题纪实或演播室风格的成片视频。创作者可将成片发布为**激励计划**，观众观看后答题获得积分奖励，形成「创作—传播—互动—激励」闭环。

**核心价值主张：**

- 对**被访者/家庭**：降低口述与制作门槛，无需写作与剪辑技能即可留下影像记忆。
- 对**创作者/机构**：通过**大规模场景与模板覆盖**，把故事创作从手工作坊变为**工业流水线**。
- 对**平台/观众**：答题观看机制提升完播与互动，适配短视频/直播等公域引流场景。

**战略重心（2026 起）：**

1. **品类扩张**：从「个人传记」扩展到**个人故事**（恋爱、军旅、科研生涯等），并延伸至**村志、县志**等集体记忆。
2. **工业化路径**：对文革、留守儿童、高考恢复等**高重复人生经历**建立标准模板与高质量可复用元素（访谈题、文本结构、年代场景包、视觉/旁白资产），一次打磨、持续复用——这是相对「用户自己写故事」的核心优势。

**当前阶段：** 核心生产链路（访谈 → 文本 → 视频）与账户体系已跑通；**活动激励 + 观看答题**在 `feature/quiz-rewards` 分支已实现后端闭环；积分钱包规则仍在产品定稿与 mock 迭代中。

## 二、项目概述

### 2.1 产品愿景

让每个人都能用一次轻松对话，留下一部可传承、可分享、可互动的故事视频；让集体记忆（村落、地方）也能以同样标准被采集、成文、成片。

### 2.2 产品 Slogan

> **把访谈变成属于你的故事视频**  
> 聊天采集 · 整理成文 · 一键成片

**对外愿景表述（建议）：**

> Hello Story：把世间重复发生的人生，做成可复用的故事工业；把每个人独有的那一部分，装配进这条流水线。  
> 从恋爱、军旅、科研到村志县志——我们覆盖场景，你填写人生。

### 2.3 目标用户

| 用户群 | 场景 | 付费意愿 |
|--------|------|----------|
| 银发族及子女 | 为父母/祖辈记录人生故事 | 中高（情感驱动） |
| 情侣与家庭 | 恋爱史、婚礼回顾、家族史 | 中 |
| 个人 IP / 自媒体 | 人物专访、品牌故事、抖音传记号 | 中（ROI 驱动） |
| 军旅/科研/公职群体 | 生涯纪实、退休仪式、单位宣传 | 中高（B2B 潜力） |
| 村委会/地方文旅 | 村志、自然村史、县志专题 | 项目制 |
| 观众用户 | 观看他人故事、答题赚积分 | 时间换积分 |

### 2.4 解决的核心痛点

1. **不会写**：口述零散 → AI 多档选题 + 智能追问结构化采集。
2. **不会剪**：视频门槛高 → 20+ 步 LLM 流水线自动生成旁白、分镜、TTS、合成。
3. **重复劳动**：同类人生经历被反复从零写起 → **标准模板 + 场景资产库**一次制作、跨用户复用。
4. **传不出去**：私域内容缺乏互动 → 激励计划 + 答题发奖驱动观看与传播。
5. **直播难展示**：浏览器 UI 不适合窗口捕获 → Electron 直播壳（430×932 竖屏）适配抖音伴侣。

## 三、战略方向

### 3.1 品类扩张：个人故事 × 集体记忆

#### 定位调整

| 原定位 | 新定位 |
|--------|--------|
| AI 个人传记平台 | **AI 故事创作与传播平台**——个人经历与集体记忆均可结构化、成片、分发 |

「传记」仍是**旗舰品类**（情感强、付费意愿高），但品牌与 catalog 覆盖更广的**人生叙事类型**。

#### 三层内容金字塔

```
L1 个人故事（规模化主力）
  ├── 恋爱与情感、军旅与公职、科研与学术
  ├── 创业与工作转折、童年与留守/迁徙
  └── 与现有 catalog（学业/工作/情感/地域/人生事件）自然衔接

L2 家庭与代际
  ├── 家族史片、婚礼与礼俗
  └── 多被访者、代际对照（未来）

L3 集体记忆（高门槛、高价值）
  ├── 村志 / 自然村史
  └── 县志片段 / 地方专题

         ↓ 统一流水线 ↓
   访谈采集 → 结构化 → 成文 → 成片 →（可选）激励分发
```

**与现有产品的衔接：**

- 当前 `template-config.v2.json` 已覆盖 **学业、家庭、工作、情感、地域、人生事件** 等大类，天然支持恋爱、工作、地域迁徙等个人故事。
- **军旅、科研、文革/特殊年代、留守儿童**等需新增 **专题 subCategory + 专用 prompt + 视频场景包**。
- **村志/县志**为新产品线：采访对象从「个人」扩展为「多人/机构/地方素材」；交付从「一条片」扩展为「章节集 + 专题片 + 图文志素材」。

#### 各品类商业特征（示意）

| 品类 | 典型客户 | 交付形态 | 单价区间 |
|------|----------|----------|----------|
| 恋爱/情感故事 | 情侣、婚礼、自媒体 | 5–15 分钟成片 | 中 |
| 军旅/公职生涯 | 个人、单位退休仪式 | 纪实风短片 | 中高 |
| 科研生涯 | 高校、实验室、学会 | 人物专题 + 口述 | 高（B2B） |
| 村志 | 村委会、乡贤、文旅 | 多集系列 + 志书素材 | 项目制 |
| 县志专题 | 地方志办、融媒体 | 模块化章节 | 政府/采购 |

### 3.2 核心战略：故事创作的工业化

#### 战略一句话

**不是帮用户「从零写故事」，而是用大规模、可复用的「人生场景模板 + 高质量素材元素」，把真实经历装配成成片——像工厂流水线，而不是手工作坊。**

#### 与用户自写的本质差异

| 维度 | 用户自己写/剪 | Hello Story 工业化路径 |
|------|----------------|-------------------------|
| 结构 | 想到哪写到哪 | **catalog 子类 + Tier 选题** 覆盖人生关键节点 |
| 重复经历 | 每人重写一遍 | **共享模板**：文革、高考恢复、下海、留守、进城务工…一次打磨、百万次复用 |
| 视觉/听觉 | 找素材难 | **场景包、时代 Backdrop、地名标牌、TTS 音色** 按年代/地域复用 |
| 质量 | 波动大 | **标准工序**（step-10…step-240）保证下限 |
| 成本 | 时间成本高 | 边际成本随复用下降 |

**价值公式：**

> 单用户价值 = 专属访谈内容（不可复用）  
> \+ 标准模板与素材（高度复用）  
> \+ 流水线工序（规模降本）

用户不可替代的是**「我的那一份事实与情感」**；平台不可替代的是**「这一类故事已经有人把坑踩完、把质量做高」**。

#### 「覆盖」的三层含义

**① 叙事模板覆盖（What to ask）**

- 为「高重复经历」建 **标准 subCategory**：如 `life_cultural_revolution`、`life_left_behind_child`、`career_military_service`、`career_research_track`。
- 每套模板包含：必填/可选字段、**Tier 热点问句**、矛盾/缺口检测规则。
- 同一模板服务成千上万个「同类不同人」的故事，仅 **sections 实例数据** 不同。

**② 场景流程覆盖（How to produce）**

- **访谈**：口语化、refine、suggest 等 prompt 按子类分支，编排层不变。
- **文本**：formal-article 按品类切换语气（纪实 / 抒情 / 方志体）。
- **视频**：传记 / 演播室 /（未来）方志纪事体——共用底层 step，替换 **era-backdrop、env-narrative、visual style** 包。

**③ 资产库覆盖（What it looks/sounds like）**

- **年代包**：60–70、80、90 年代…视觉与旁白基调。
- **地域包**：县城、村庄、工厂、校园… geo-signage、环境描述模板。
- **母题包**：离别、重逢、第一次、转折… 可参数化 emotional-inner 类 prompt。
- 这些资产**一次制作、跨用户复用**，是毛利率的核心来源。

#### 工业化飞轮

```
更多用户完成同类故事
    → 结构化 sections 沉淀
    → 识别高频节点与表述
    → 升级 catalog / prompt / 场景包
    → 质量上升 + 成本下降
    → 吸引更多用户
```

- **早期**：产品与设计**人工定义**高频模板（文革、留守、高考等）。
- **中期**：**脱敏聚合**优化问句顺序、跳过率、成片完播。
- **后期**：新品类（村志）= **已有流水线 + 新 catalog 层**，而非重做系统。

### 3.3 竞争壁垒（战略层）

1. **模板广度 × 深度**：不是空分类，而是每个子类带完整 **访谈→成片** 链路。
2. **场景资产库**：时间越久、覆盖越全，后来者越难补齐。
3. **双边网络**（激励计划）：个人故事与村志专题均可成为 **观看+答题** 内容供给。
4. **流水线工程化**：选题编排（Tier1–8）、视频 Worker、日终发奖调度等已代码化，非 demo 级套壳。

## 四、市场分析

### 4.1 市场背景

- **口述史 / 数字遗产**：60 后、70 后进入「故事留存」需求高峰期。
- **AIGC 内容生产**：LLM + TTS + 文生图使「一人成片」成本较传统纪录片显著下降。
- **短视频互动**：抖音等平台鼓励看播 + 互动；答题、积分与平台生态兼容。
- **地方文化振兴**：村志、县志、非遗口述与政策与文旅投入相关。

### 4.2 市场规模（定性）

| 层级 | 描述 |
|------|------|
| TAM | 关注「家庭记忆 / 个人故事 / 地方记忆」的互联网用户（亿级） |
| SAM | 愿意用 App 完成创作并分享的 35–65 岁用户及其子女 + 基层文化机构（千万级） |
| SOM（首年） | 垂直传记号、家族用户、村志试点（万–十万级） |

### 4.3 竞争格局

| 类型 | 代表 | Hello Story 差异 |
|------|------|------------------|
| 相册/回忆录 App | 各类家庭云相册 | **AI 访谈 + 视频成片 + 模板工业化** |
| 通用 AI 视频 | 可灵、Runway 等 | 聚焦 **人生叙事 catalog + 长访谈结构** |
| 人工传记服务 | 口述史工作室 | **低成本、可自助、可规模化** |
| 问答/激励平台 | 看播任务类 App | **内容本身为原创故事**，情感粘性更高 |

## 五、产品与服务

### 5.1 用户旅程

```
登录 → 故事墙 → AI 采访聊天 → 创作文本 → 创作视频
    →（可选）发布激励计划 → 观众观看答题 → 日终积分发奖
```

### 5.2 功能模块

| 模块 | 能力 | 状态 |
|------|------|------|
| 故事墙 | 多故事管理、封面展示、进入创作 | 已上线 |
| AI 采访 | 8 档选题（catalog / 热点 / 矛盾 / 缺口 / 转折 / 内心等） | 已上线 |
| 创作文本 | 访谈素材 → 正式故事正文 | 已上线 |
| 创作视频 | 传记流水线 + 演播室风格 | 已上线（Worker 异步） |
| 活动 Tab | 激励计划、选题、关联成片 | quiz-rewards 分支 |
| 观看 Tab | 今日任务 Feed、播放、答题 | quiz-rewards 分支 |
| 积分钱包 | 充值、份执行扣款、答题发奖 | 后端已实现，规则迭代中 |
| 多语言 | 中文原生写入 + 英文 display | 方案 A 推进中 |
| 直播壳 | Electron 窗口捕获推流 | desktop/ 已提供 |

### 5.3 技术架构概要

- **前端**：React + Vite + Capacitor（iOS/Android）+ Electron 直播壳。
- **后端**：Express + SQLite + 用户工作区磁盘（采访/选题/生产产物）。
- **Worker**：视频流水线单进程 FIFO 队列（PM2/systemd）。
- **AI**：OpenAI 兼容 API；SMS（阿里云）+ Apple 双通道登录。

相关文档：`backend/docs/http-api.md`、`docs/topic-selection-module.md`、`backend/docs/quiz-rewards.md`、`backend/docs/video-worker.md`。

## 六、商业模式

### 6.1 收入来源

| 模式 | 说明 | 优先级 |
|------|------|--------|
| 积分消耗 | 文本/视频生成按次或按 tier 扣积分 | P0 |
| 模板/风格 Premium | 军旅纪实包、科研口述包、婚礼电影包、年代场景包 | P1 |
| 激励计划服务费 | 创作者发布计划时平台抽成或通道费 | P1 |
| 会员订阅 | 每月 N 次免费生成 + 高级风格 | P1 |
| B2B / G 端项目 | 村志整村、县志专题、单位史馆 | P2 |
| 资产授权 | 年代视觉包、场景库对 MCN/平台授权 | P2 |
| 直播引流 | 传记号直播演示流水线，导流到 App | P2 |

### 6.2 积分经济模型（基于现有设计）

- 创作者设定 **年度积分预算**，系统按 **100 份/年** 均匀注入奖池；到执行日才从钱包扣款。
- 观众答对每题获得 **固定积分**（日终 23:00 到账）。
- 平台可在 **充值** 或 **计划创建** 环节收取溢价。

详见 `backend/docs/quiz-rewards.md`。

### 6.3 成本结构与工业化优势

- **变动成本**：LLM（访谈、选题、文本、视频各步）、TTS、文生图、存储与 CDN。
- **研发摊销**：每新增一个「文革经历」或「留守童年」模板，服务 N 个用户，prompt 与视频 step 调优成本**相对固定**。
- **生成成本**：相同 era-backdrop / 环境叙事模板减少 LLM 发散与文生图试错。
- **关键指标**：单次成片 API 成本、模板复用命中率、用户 LTV、激励计划 ARPU。

### 6.4 单位经济（框架，需实测）

- Year 1 注册用户：1–5 万；付费转化率 3–8%。
- 人均年 ARPU（积分+会员）：80–300 元（示意）。
- 单次传记/专题视频变动成本：15–80 元（视 LLM/TTS/图量而定）。

## 七、运营与增长

### 7.1 冷启动

1. **家族场景**：「给爸妈录一个故事」+ 子女代操作。
2. **抖音传记/故事垂类**：Electron 壳窗口捕获直播，展示访谈/成片过程。
3. **激励计划内测**：邀请创作者发布计划，用积分拉首批观众完播+答题。
4. **模板话题营销**：「你的文革岁月」「留守儿童的童年」等标准包作为传播钩子。

### 7.2 留存

- 多故事墙：一人多传记（自己、父母、配偶）。
- 访谈未完成提醒、新 Tier / 新专题模板推荐。
- 观众侧：每日观看任务 + 积分到账。

### 7.3 品牌调性

温暖、尊重、非审问式采访；模板强调**个人经历**而非政治论述（敏感题材需审核策略）。

## 十、风险与对策

| 风险 | 对策 |
|------|------|
| 成片质量不稳定 | 分步测试、人工抽检、失败重试与用户预览 |
| AI 成本过高 | 分级模型、模板复用、按 tier 限流 |
| 内容失真/幻觉 | 矛盾检测 Tier、用户确认、免责声明 |
| 敏感历史题材 | 内容安全策略、个人经历边界、审核流程 |
| 村志/县志事实性 | 多人交叉采访、人工监制、项目制交付 |
| 模板化 vs 真实感 | 强调模板管结构与质量，个性来自 sections；可选分支增加差异 |
| 积分合规 | 明确积分性质、律师 review |

---

## 十一、结论

Hello Story 占据 **「AI + 人生叙事 + 视频工业化 + 互动激励」** 的交叉赛道。短期应 **固化积分商业规则、合并激励分支、以标准经历模板库建立差异化**；中期以家庭情感场景与抖音直播验证获客；长期以 **模板与资产库覆盖** 形成成本与质量壁垒，并向 **村志县志** 等集体记忆延伸。

**核心信念：**

> 世间有大量重复发生的人生，值得用工业级模板与资产去覆盖；  
> 每一个具体的人，仍应在流水线里留下只属于自己的那一部分。
